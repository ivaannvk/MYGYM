1. Contexto & Problemática

¿Por qué nace el proyecto Mi Gym?

❌ El Problema Actual

Los entrenadores personales utilizan hojas de Excel dispersas, notas en el móvil o mensajes de WhatsApp desordenados. Los clientes no entienden cómo ejecutar los ejercicios ni disponen de alternativas en sus comidas.

❌ Falta de Detalle en Cargas

Las apps habituales marcan "4 series de 10 reps", pero no permiten especificar el peso exacto de la Serie 1 (70kg), Serie 2 (75kg) o Serie 3 (80kg al fallo).

💡 Nuestra Solución

Una plataforma web ágil y profesional donde el entrenador confecciona planes precisos con vídeo y dietas multi-opción, enviándolas al cliente en 1 clic por WhatsApp.

http://localhost/paginaweb/

🚀 Todo en una Sola Plataforma

Diseño limpio, sin suscripciones caras ni software sobrecargado.

2. Alcance del Proyecto

Objetivos Principales y Propuesta de Valor

🎯 Objetivo General

Desarrollar una aplicación web modular en PHP y MySQL con interfaz responsiva para la confección y distribución omnicanal de rutinas de fuerza y planes de nutrición personalizados.

  • 1. Catálogo Nutricional Propio: Base de datos de alimentos con cálculo de macronutrientes por 100g editable por el profesional.
  • 2. Soporte Multimedia Sin Límites: Subida de vídeos MP4 en servidor o enlaces a Drive/YouTube para cada ejercicio.
  • 3. Planes Multi-Menú: Alternativas equivalentes de comidas (Día 1, Día 2...) calculando totales dinámicamente.

⚡ Eficiencia Operativa

Reduce el tiempo de confección de una dieta y rutina de 45 minutos a menos de 5 minutos.

📲 Adherencia del Cliente

El cliente consulta su rutina en el gimnasio desde WhatsApp con vídeos integrados sin instalar ninguna app externa.

3. Tecnologías Empleadas

Stack Tecnológico y Arquitectura

🎨 Frontend (Cliente)

HTML5 Semántico, CSS3 Moderno (Variables, Grid, Flexbox y @media print) y JavaScript Vanilla ES6+ para interactividad reactiva sin sobrecarga de librerías.

⚙️ Backend (Servidor)

PHP 8.x modular y orientado a procesos, con validación de peticiones multipart/form-data, sesiones y APIs de integración.

🗄️ Capa de Datos

MySQL / MariaDB (InnoDB) con sentencias preparadas (Prepared Statements), transacciones e integridad referencial en cascada.

Arquitectura Cliente - Servidor
// Flujo de Peticiones y Respuestas
1. Cliente envía FormData [Multipart/POST]
2. Apache procesa directivas (.htaccess 1000M)
3. PHP valida tipos MIME y sanea entradas
4. MySQL ejecuta Prepared Statements ($stmt)
5. Retorno HTML + JS reactivo en tiempo real

12. Aspectos Técnicos

Seguridad, Rendimiento y Buenas Prácticas

🛡️ Prevención de Inyección SQL

Uso sistemático de Sentencias Preparadas (Prepared Statements) con mysqli_stmt en todas las operaciones de base de datos.

🔒 Protección contra Cross-Site Scripting (XSS)

Escape y sanitización de todas las salidas dinámicas con htmlspecialchars().

📁 Subida Segura de Archivos

Filtrado de extensiones válidas de vídeo, renombrado criptoseguro para evitar ejecución de scripts maliciosos y aislamiento de rutas.

Seguridad de Backend (PHP)
// Sentencia Preparada Segura
$stmt = $conexion->prepare(
  "INSERT INTO rutina_ejercicios ... VALUES (?, ?, ?)"
);
$stmt->bind_param("isi", $rutina_id, $ej, $series);
$stmt->execute();

// Prevención XSS
echo htmlspecialchars($fila['nombre']);
